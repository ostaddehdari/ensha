# انشا · نسخه ۰.۳ مدیریت دسترسی

این بسته، پنل Laravel مسیر `https://srun.ir/ensha/` با رابط Metronic Tailwind RTL است. در نسخه ۰.۳ بخش «کاربران، نقش‌ها و دسترسی‌ها» از لایهٔ دیتابیس تا سیاست‌های امنیتی، رابط کاربری و آزمون‌های خودکار تکمیل شده است. بخش‌های نوبت، پرونده، آزمون و پرداخت همچنان برای مرحله‌های بعدی به‌صورت آماده‌سازی‌شده باقی مانده‌اند.

## امکانات تکمیل‌شده

- شش نقش سیستمی: ادمین سیستم، مدیر مرکز، منشی، مشاور، مسئول تست و مراجعه‌کننده.
- نقش سفارشی با دامنهٔ سراسری/مرکز، وضعیت فعال و ماتریس ۳۵ مجوز در ۱۰ گروه عملیاتی.
- فهرست کاربران با جست‌وجو، فیلتر نقش/مرکز/وضعیت، صفحه‌بندی و خروجی CSV محدود به دامنهٔ مجاز.
- ایجاد، مشاهده و ویرایش حساب با اعتبارسنجی شماره همراه و کد ملی ایران.
- سه وضعیت حساب: فعال، غیرفعال و مسدود؛ همراه با دلیل، زمان و عامل تغییر.
- بازنشانی رمز موقت، الزام تغییر رمز در ورود بعدی و ابطال همهٔ نشست‌های قبلی.
- نمایش دستگاه‌ها و نشست‌های اخیر و امکان پایان‌دادن یک نشست یا همهٔ نشست‌ها.
- حذف نرم، سطل زباله و بازیابی حساب به‌صورت غیرفعال.
- ورود موقت و ثبت‌شدهٔ ادمین به پنل کاربر، با نوار هشدار دائمی و خروج امن.
- ثبت رویدادهای حساس با عامل، هدف، نوع عملیات و مقادیر قبل/بعد.
- محدودسازی مدیر مرکز به کاربران مرکز خودش و جلوگیری از واگذاری مجوزی فراتر از اختیار او.
- حفاظت از حساب جاری، آخرین ادمین، نقش‌های سیستمی و نقش‌های دارای کاربر.
- محدودسازی نرخ ورود، ثبت‌نام، عملیات حساس و خروجی‌گیری.
- نمایش IP و جزئیات دستگاه فقط به صاحب حساب یا مدیر دارای مجوز ابطال نشست.

## پیش‌نیازها

- Ubuntu 24.04 یا معادل آن
- PHP 8.3 یا جدیدتر
- MySQL/MariaDB یا PostgreSQL
- Composer 2
- افزونه‌های متداول PHP برای Laravel

روی Ubuntu:

```bash
sudo apt update
sudo apt install -y php8.3-cli php8.3-mbstring php8.3-xml php8.3-curl \
  php8.3-bcmath php8.3-mysql php8.3-sqlite3 unzip composer
```

## نصب تازه

پروژه را در `/var/www/ensha` استخراج و ابتدا اتصال دیتابیس را در `.env` تنظیم کنید:

```bash
cd /var/www/ensha
cp .env.example .env
nano .env
sudo bash deploy/install.sh
```

نصب‌کننده وابستگی‌ها را از `composer.lock` نصب، کلید برنامه را فقط در صورت خالی‌بودن ایجاد، migration و seed اولیه را اجرا و سرویس `ensha-web` را روی `127.0.0.1:18850` فعال می‌کند.

ورود اولیهٔ نصب تازه:

```text
ادمین سیستم: 09120000000 / ChangeMe123!
مدیر مرکز:   09120000001 / ChangeMe123!
```

حساب‌های نمونه در نخستین ورود مجبور به تغییر رمز هستند. پیش از در دسترس قراردادن عمومی سامانه، همهٔ رمزهای نمونه را تغییر دهید.

در صورت نصب Composer در مسیر غیرمعمول:

```bash
sudo COMPOSER_BIN=/usr/local/bin/composer bash deploy/install.sh
```

## اتصال به nginx موجود

در server block دامنهٔ `srun.ir` این خط را قرار دهید:

```nginx
include /var/www/ensha/nginx/ensha-location.conf;
```

سپس:

```bash
sudo nginx -t
sudo systemctl reload nginx
sudo systemctl status ensha-web --no-pager
```

مسیر `/ensha/` از طریق reverse proxy به سرویس داخلی متصل می‌شود و دیتابیس آن از WordPress مستقل است.

## ارتقای نصب موجود از نسخه ۰.۲

بسته را، برای نمونه، در `/tmp/ensha-v0.3` استخراج کنید و اجرا کنید:

```bash
sudo bash /tmp/ensha-v0.3/ensha-base/deploy/update-v0.3.sh \
  /tmp/ensha-v0.3/ensha-base /var/www/ensha
```

اسکریپت ارتقا پیش از تغییر کد یک نسخهٔ پشتیبان در `/var/backups/ensha/` می‌سازد؛ سپس برنامه را موقتاً در حالت نگهداری می‌گذارد، کد و migrationها را منتقل، migration را بدون seed اجرا و سرویس را همراه با بررسی سلامت راه‌اندازی می‌کند. فایل‌های `.env`، `storage`، `vendor`، `composer.lock` و داده‌های دیتابیس موجود حفظ می‌شوند؛ بنابراین حساب‌ها و رمزهای فعلی بازنشانی نخواهند شد.

پس از ارتقا، صفحه را با `Ctrl+F5` باز کنید و نتیجه را کنترل کنید:

```bash
cd /var/www/ensha
sudo -u www-data php artisan migrate:status
sudo -u www-data php artisan route:list --except-vendor
curl -fsS http://127.0.0.1:18850/up
sudo systemctl status ensha-web --no-pager
```

برای HTTPS این تنظیمات باید در `.env` فعال باشند:

```dotenv
APP_URL=https://srun.ir/ensha
SESSION_PATH=/ensha
SESSION_ENCRYPT=true
SESSION_SECURE_COOKIE=true
```

## مدل دسترسی

- ادمین سیستم دامنهٔ سراسری دارد و تنها نقش مجاز برای مدیریت کامل نقش‌ها، حذف/بازیابی و ورود موقت است.
- مدیر مرکز فقط کاربران همان مرکز را می‌بیند و نقش‌های مجاز مرکز را واگذار می‌کند.
- یک نقش سفارشی نمی‌تواند توسط مدیری واگذار یا مدیریت شود اگر حتی یکی از مجوزهایش خارج از اختیارات آن مدیر باشد.
- تغییر نقش/وضعیت حساب جاری، مدیریت مدیر دیگر توسط مدیر مرکز و حذف نقش سیستمی مسدود است.
- همهٔ عملیات حساس از مسیر Policy، محدودکنندهٔ نرخ و Audit Log عبور می‌کنند؛ مخفی‌کردن دکمه در رابط، تنها لایهٔ کنترل نیست.

## توسعه و آزمون

در محیط توسعه، پس از نصب وابستگی‌های dev:

```bash
composer install
vendor/bin/pint --test
vendor/bin/phpunit
composer audit --locked
```

آزمون‌ها دامنهٔ مرکز، جلوگیری از ارتقای سطح دسترسی، تغییر وضعیت، رمز موقت، ابطال نشست، حذف/بازیابی، ورود موقت، خروجی محدود و رندر صفحات مدیریتی را پوشش می‌دهند.
